# Phase 6：提及、站内通知与讨论发现

只在本机运行和验证，Test/Production 业务写入继续关闭，没有部署或创建云资源。

## @ 用户解析

使用固定用户名 `@u_<认证 ID>`；主页和账户设置可查看用户名。原有开发作者保留其旧用户名。显示名称不是唯一标识，不用于提及匹配。

普通 Markdown 文本中的 `@username` 转成 `/member/:username` 链接，继续经过同一个 sanitizer。规则支持 ASCII 字母、数字、下划线和连字符，最长 80 字符，区分大小写；邮箱、URL 路径中的 @ 不匹配。代码、行内代码、已有链接、图片、原始 HTML 节点和整段 blockquote 不参与提及，因此引用按钮产生的引文不会再次通知原作者。

提取与渲染共用 `src/lib/mentions.ts` 的 AST 扫描规则，每篇内容只处理前 20 个不同用户名，重复用户名去重。按 Markdown 解析后的可见文本识别；需要展示 @ 文字而不触发提及时请使用行内代码或引用。语法合法但不存在的用户名仍显示链接，主页返回 404，不生成通知。未验证或被封禁账户也不会收到通知。

0007 为既有认证用户补齐缺失 profile，并通过注册触发器初始化固定标识；不会覆盖已有显示名称、简介、头像或用户名。未验证账户的初始化资料不对外公开。旧开发身份 user_id=NULL 继续可浏览，但不是认证账户或通知收件人。

## 站内通知

- 新主题：通知正文中的有效提及对象。
- 新回复：通知主题作者和正文中的有效提及对象；同一收件人合并一条，显式提及时 kind=mention，否则 kind=reply。
- 编辑：只补发给此前没有收到这条内容通知的提及对象，不重复提醒保留的 @。主题标题不参与提及。
- 不给自己、未知用户、未验证或被封禁用户投递。不回填历史通知；旧内容在新编辑时按当前规则处理。
- 唯一键为收件人 + 来源内容，原始发帖/回复/编辑和一条合并通知 INSERT 在同一个 D1 batch。`changes()=1` 绑定前一个业务写入，故障则整个 batch 回滚；不能用“期望 revision+1 恰好存在”替代是否成功写入。重复 requestId、冲突或越权编辑不通知。

`/notifications` 是私有 SSR 页面，导航显示当前可见的未读数。每页 20 条，按时间和不透明 ID 倒序游标分页；可逐条标记已读，重复操作不改变首次 read_at。来源为回复时，链接定位到所在楼层分页。

通知只保存来源 ID、操作者、类型与时间，不保存原正文或摘要。列表、未读数、已读 SQL 都检查当前收件人、封禁及主题/节点/回复可见性；隐藏/删除后不返回标题等元数据，也不能标记已读。恢复隐藏内容后旧通知可重新出现，保持原已读状态。提及从正文移除后仍保留已经发生的通知事件，显示的是当前内容标题。

API 均位于 `/api/v1`：GET `/notifications?cursor=` 返回 items、nextCursor、unread；PATCH `/notifications/:id/read` 接收 `{}`。身份来自已验证邮箱的 Session，不接受 recipientId。已读写入仍要求本机、精确 Origin 和 JSON。没有邮件、推送、轮询或 WebSocket 通知，刷新页面时更新未读数。

## 基础搜索与排序

首页、节点页和用户主页共享搜索/排序表单。GET `/api/v1/topics?q=&sort=&node=&cursor=` 使用同一查询，节点和作者页面继续保留对应范围。

| 参数        | 行为                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------- |
| q           | 空值或 2–80 字符，去除首尾空格，拒绝 NUL；标题/正文连续子串匹配，支持中文                    |
| sort=latest | 发布时间倒序，默认值                                                                         |
| sort=hot    | 全部公开主题按 `3 × vote_count + reply_count` 倒序                                           |
| sort=active | `coalesce(last_replied_at, created_at)` 倒序；编辑不顶帖，删除最后有效回复会按既有触发器回落 |

同分再按创建时间、主题 ID 倒序，每页 20 条；游标包含排序值/时间/ID，并校验 sort 与 q 一致。旧 latest 游标保持兼容。翻页链接保留筛选参数，改变筛选从首屏开始；未知排序、错误游标和不合法关键词返回 400。

搜索采用参数化 LIKE，`!`、`%`、`_` 按字面转义，不开放 SQL 或 FTS 查询语法。ASCII 大小写遵循 SQLite LIKE 行为；没有分词、模糊匹配、相关性排名、回复全文检索或搜索摘要。隐藏/删除主题、隐藏节点始终过滤；不返回隐藏内容的命中数量或片段。

热门和活跃是实时值，不是跨请求快照：翻页期间点赞/回复变化可能让项目跨页移动，刷新首屏获取新顺序。本阶段未增加快照排行或缓存。

热门/活跃增加表达式索引，普通关键词的前导通配符 LIKE 仍可能扫描公开主题，本机测试不能代表大数据量或云端 D1 成本。规模扩大前应以实际数据评估 FTS/分词与查询配额，不提前引入外部搜索服务。
